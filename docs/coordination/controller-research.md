# Controller implementation knowledge

Reviewed 3 November 2026. Request R23 now covers **all NI controllers and class-compliant MIDI controllers**, including hardware marketed for Serato, Pioneer DJ/AlphaTheta and other DJ systems. Z1 Mk1 remains first. A hardware bridge is allowed. The app target remains the A10X iPad.

## Evidence rules

Use the manufacturer's MIDI/protocol manual for addresses and units. Use maintained implementation/protocol research where the manufacturer does not publish them. Record a source and a separate implementation/hardware result. Do not infer full support from USB detection, an audio device, a brand name or another application's compatibility badge.

The generic input layer must remain independent of vendor profiles. A controller profile defines messages, value encoding, modifiers, deck/layer assignment, jog/touch interpretation and output behaviour. It must not contain executable downloaded code. Unknown handshakes and raw reports remain unsupported until verified.

## Implemented increment

- Absolute MIDI controls and full pitch-bend values.
- Explicit paired-14-bit CCs. Partial low-byte state cannot operate a control before its MSB.
- Three relative encodings with reversible direction. Continuous controls are coalesced per input drain.
- Note buttons, poly/channel pressure and program-change button events.
- Existing transport, mixer, filter, FX, ±8% tempo, loops, Beat Jump, Freeze and eight hotcues per deck exposed to Learn.
- One optional momentary Shift button selects a second set of learned mappings.
- An opt-in DDJ-FLX4 profile maps the published transport, mixer, Hot Cue, vinyl-on and vinyl-off platter jog and touch messages, plus wheel-side CC 33 as a temporary rate bend. The default bend is bounded to eight percent and resets after 150 ms without input. Hot Cue pads require Hot Cue pad mode. It replaces mappings only for the selected MIDI input after confirmation. Other light feedback remains unmapped.
- An opt-in DDJ-REV1 profile maps the published dual-deck play, cue, sync, channel mixer, tempo, loop-size, loop-toggle, Hot Cue pad, vinyl-on/off jog, platter-touch, wheel-side jog and momentary Shift messages. Hot Cue pads require the controller's Hot Cue mode. It replaces mappings only for the selected MIDI input after confirmation.
- An opt-in DDJ-REV5 profile maps the published two-deck play, cue, sync, channel mixer, tempo, loop-size, loop-toggle, Hot Cue pad, jog/touch, wheel-side jog and momentary Shift messages. It also maps REV5 play, sync, headphone-cue and Hot Cue light messages on a selected MIDI output. Deck 3/4 controls and other pad modes remain unmapped. Both pad banks must be in Hot Cue mode. The profile replaces mappings only for the selected input or output after confirmation.
- An opt-in DDJ-FLX10 profile maps the published two-deck transport, paired-14-bit mixer and tempo, loop controls, Beat Jump, Hot Cue pad, jog/touch, wheel-side jog and momentary Shift messages. A separate optional output profile maps play, sync, headphone-cue and Hot Cue lights, with fixed Hot Cue colour values. Deck 3/4 and stem controls remain unmapped. Hot Cue pads require Hot Cue mode. Each profile replaces mappings only for its selected input or output after confirmation.
- A separate DDJ-FLX4 output profile maps play, sync, headphone-cue and Hot Cue lights on the selected MIDI output. It replaces only those actions, and MIDI feedback stays off until the user enables it.
- A separate DDJ-REV1 output profile maps play, sync, headphone-cue and Hot Cue lights on the selected MIDI output. It replaces only those actions, and MIDI feedback stays off until the user enables it.
- A separate DDJ-REV5 output profile maps play, sync, headphone-cue and Hot Cue lights on the selected MIDI output. It replaces only those actions, and MIDI feedback stays off until the user enables it.
- Core MIDI input requests MIDI 2.0 UMP and decodes supported MIDI 1.0 and MIDI 2.0 channel voice messages. It preserves UMP group identity and full controller precision through the shared `Double` action path. The Z1 SysEx bridge stays on the legacy byte input.
- The UMP decoder handles MIDI 2.0 registered and assignable controllers, relative variants, per-note registered and assignable controllers, and per-note pitch bend. Learned bindings retain parameter and note identity. Per-note management and other unmapped UMP types remain ignored.
- MIDI 2.0 Program Change bindings retain the bank when the Bank Valid flag is set. The note decoder distinguishes MIDI 2.0 Note On at zero velocity from Note Off so learned button actions can still trigger.
- User-configured generic MIDI Note/Control Change feedback, scoped to the selected output destination.
- Original Z1 development bridge framing, Linux HID relay, calibration, native input and light/meter output route.

This does not finish all controller support. Verified model profiles, jog/touch, model-specific modifier behaviour, simultaneous input selection, soft takeover, native displays/motors and actual bridge audio remain open. Physical Z1 and bridge acceptance remain with Erik.
